# Book news: implementation plan

**Goal:** a "Book news" feed in the app and on the website, listing recent book-industry news (Portuguese and English) and a calendar of recurring book events.

**Architecture:** this uses the same pattern as "New in Portugal". A scheduled GitHub job reads public RSS/Atom feeds, keeps the last 30 days as headline, short summary, source, date and link, and publishes `news/news.json` with the GitHub Pages site. It sits beside `news/events.json`, a hand-kept calendar.
- **Website:** shows it on a lazy `/news` page.
- **App:** shows it on a "Book news" screen, cached for offline.
- **Links:** a story opens the original article in the browser.

There are no paid APIs and no server.

**User decisions** (2026-11-17, "dive in"):
- The pattern above.
- The sources checked below.
- Headline, summary and link only, never full articles (copyright).

## Global constraints
- **Sources:** free, public RSS/Atom feeds only. No scraping of shops or paywalled pages.
- **Identity:** send an honest User-Agent: `MyBooks-news/1.0 (+https://marioruidacosta.github.io/MyBooksNewGeneration/)`.
- **Text:**
  - Summaries are plain text: HTML stripped and entities decoded, at most 280 characters, cut at a word boundary and ended with "…".
  - Titles are at most 200 characters.
- **Links and images:** only `https:` links are kept. Images are kept only if they are `https:`, otherwise null.
- **Robustness:** one failing feed never fails the build. If every feed fails, the previous published `news.json` is kept, because the job first fetches the live file and merges with it.
- **Copy:** plain short English, sentence case, straight apostrophes. The two web themes (Night default, Paper) apply, and so do the app's light and dark themes.

## Output: `news/news.json`
```json
{ "generatedAt": 1794870000000,
  "sources": [{ "id": "apel", "name": "APEL", "lang": "pt", "ok": true }],
  "items": [{ "id": "<sha1 of url>", "title": "…", "summary": "…", "url": "https://…", "source": "apel",
              "lang": "pt", "published": 1794860000000, "image": "https://…" }] }
```
- Items are newest first, at most 200, and only from the last 30 days by `published`.
- A missing date counts as fetch time.
- Items are deduped by normalised URL (no query or hash), then by identical title.
- `events.json` is already written at `web/public/news/events.json`, so Vite copies it to the build. Don't change its entries.

### Task 1: The news job
**Files:**
- Create: `web/scripts/news/build-news.ts`, `web/scripts/news/feeds.ts` (the sources table), `web/scripts/news/parse.ts`, and the tests `web/scripts/news/*.test.ts` with fixtures in `web/scripts/news/fixtures/`.
- Modify: `.github/workflows/web-pages.yml`, `web/package.json`, `docs/social-setup.md` (one paragraph).

**Behaviour:**
- `parse.ts` parses RSS 2.0 and Atom with `fast-xml-parser`. Add it to devDependencies.
  - It reads the title, link, description/summary/content, the date (`pubDate`, `published`, `updated`, `dc:date`) and an image (`media:content`, `media:thumbnail`, `enclosure` with an image type, or the first `<img>` in the description).
  - It then normalises everything to the item shape above.
- `build-news.ts` takes `--out <dir>` and `--previous <url>`:
  1. Fetch every feed in parallel, with a 20 s timeout each.
  2. Apply the filters.
  3. Merge with the previous live file's items.
  4. Apply the 30-day window, dedupe, sort and cap.
  5. Write `<out>/news.json`.
  6. Log one line per source: items, or the error.
- Run it with `npx vite-node scripts/news/build-news.ts`. vite-node ships with vitest.
- In `web-pages.yml`:
  - Add `schedule: - cron: '15 5 * * *'` alongside the existing triggers.
  - Add a step after the website build that runs the script with `--out ../_site/news --previous https://marioruidacosta.github.io/MyBooksNewGeneration/news/news.json` (from `web/`). `events.json` reaches `_site/app/news/` through Vite's `public/` folder.
  - Publish both files at `_site/news/`: copy `web/public/news/events.json` there too, so the app has one base URL, `…/MyBooksNewGeneration/news/`.

**Tests:**
- `parsesRssItems`, `parsesAtomEntries` (real fixtures saved once from Guardian and APEL, trimmed to 3 items each).
- `stripsHtmlAndCapsTheSummary`, `keepsOnlyHttpsLinksAndImages`.
- `rtpKeepsOnlyBookStories`.
- `dedupesByUrlThenTitle`, `keepsThirtyDaysNewestFirstAtMost200`.
- `aFailingFeedDoesNotFailTheBuild`, `mergesWithThePreviousFile`.

**Files:**

- Modify: `web/src/App.tsx`, adding a lazy `/news` route behind sign-in and a nav link "Book news" after "Year in books". Also `web/src/theme.css`.

**Behaviour:**

- **Header:** "Book news", with "Updated <formatDay + time>".
- **Language filter:** chips for All, Português and English. Remember the choice in localStorage.
- **Stories:** grouped under day headings: "Today", "Yesterday", then `formatDay`. Each story shows:
  - the source name;
  - the title in the serif, as a link with `target="_blank" rel="noopener"`;
  - the summary;
  - the image if there is one: small, lazy-loaded, `referrerPolicy="no-referrer"`, and hidden if it fails to load.
- **"Book calendar":** a side column on wide screens, below the stories on narrow ones. It lists events from the current month onward, wrapping round the year, in the form "Usually in October · Frankfurt", each name linking to its site. Don't use middle dots; write "Usually in October, Frankfurt".
- **States:**
  - Empty or failing: "Couldn't load the news. Try again later." with a Retry button.
  - Loading: skeleton lines.

**Tests:**

## Review focus
- A feed with bad XML, or an HTML error page served as 200, must neither crash the job nor publish junk.
- Summaries must never contain HTML or script. Every link the site renders must be `https:` and open safely.
- Bad nights must not wipe the published feed. Merging with the previous file must keep it within 30 days.
- The app must be usable offline from the cache, and a failed refresh must never clear the cache.
